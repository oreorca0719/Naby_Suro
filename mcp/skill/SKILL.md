# 나비 길드 지하수로 트래커

'나비' 길드의 주간 지하수로 점수를 인게임 스크린샷에서 뽑아, 대시보드용 XLSX(순위/닉네임/직업/지하수로)로 만들고 DynamoDB 업로드까지 안내하는 파이프라인이다. 매 주차 새 세션에서 이 스킬만으로 전 과정이 동작해야 한다.

## 입력 (사용자가 주는 것)

1. **인게임 스크린샷 10~12장** — 길드 지하수로 랭킹 화면. 컬럼: `닉네임 | 직업 | 레벨 | 직위 | 주간미션 | 지하수로 | 플래그레이스`. 지하수로 내림차순 정렬 상태로 스크롤하며 찍은 것. 카카오톡 캡처(저해상도)일 수도 있음.
2. **길드원 명단(JSON)** — `"guild_member": [...]` 형태. 본캐+부캐가 모두 들어있는 정식 닉네임 목록(수백 개). **철자 정답지**로만 쓴다(닉/직업 정규화 기준). 명단에 있다고 참여자는 아님.
3. **주차 날짜** — 예: `20260709~20260715` 또는 `0709~0715`. 파일명·업로드 키에 쓴다.

명단이나 날짜가 빠졌으면 정중히 요청한다.

## 출력

`guild_members_YYYYMMDD_MMDD.xlsx` — 4컬럼 **순위 / 닉네임 / 직업 / 지하수로**, 지하수로 내림차순. TOP3 금·은·동 음영, 헤더 고정, `맑은 고딕` 폰트, 지하수로 천단위 콤마. `scripts/generate_xlsx.py`로 생성한다(직접 openpyxl 코드 새로 짜지 말 것).

## 처리 절차 (매번 이 순서)

### 1) 전 스크린샷에서 행 추출
각 캡처의 모든 데이터 행을 읽는다. `지하수로` 컬럼 큰 숫자가 점수다. 0점/미참 행도 포함한다(벌금·미참 추적에 필요). 저해상도로 안 읽히는 닉/괄호는 크롭 확대(`references/pipeline.md`의 확대 팁) 후 다시 읽는다.

### 2) 본캐 환산 — 괄호 규칙 (핵심)
패치 이후 부캐도 목록에 잡힌다. **본캐만** 남긴다:
- `A` (괄호 없음) → 본캐 = A
- `A(A)` (안=밖) → 본캐 = A (본캐 접속 중)
- `A(B)` (안≠밖) → 본캐 = **B** (괄호 안이 본캐, 수로 참여 캐릭터)

부캐 접속행(밖=부캐, 안=본캐)은 **닉네임을 본캐로 바꾸고, 직업도 본캐 직업으로 백필**한다(행에 보이는 직업은 접속 중인 부캐 것이므로). 본캐 직업은 **직전 주차 xlsx**에서 가져온다. 게임이 괄호 안을 `..`로 잘라 못 읽으면, 명단의 부캐 그룹 인접성 + 직전 주 점수 연속성으로 추정하고 사용자에게 확인받는다.

### 3) 중복·경계 제거
- **완전 동일 캡처**(같은 페이지 2번) → 1장만.
- **경계 겹침**(앞 장 마지막 행 = 다음 장 첫 행, 닉+점수 동일) → 1번만.

### 4) OCR 정규화
닉/직업을 **명단의 정식 철자**로 맞춘다. 반드시 지킬 것:
- 직업 **`윈드브레이커`** (활 계열). `워드브레이커`는 존재하지 않는 오표기 — 절대 쓰지 말 것.
- 자주 나오는 정규화·개명은 `references/pipeline.md`의 표를 따른다(예: 츄쭈, 바이루욜, 몬갸, 토77l검사, M0NCLER, 서쑤연, 표얘진, 찬죤 / 개명: 딩띠=딩팬무, 냠순=미니냥이).

### 5) 교차검증 (필수)
`scripts/generate_xlsx.py --last <직전주 xlsx>` 로 대조 리포트를 낸다:
- **신규**(직전 주 없음), **이탈**(이번 주 없음), **중복**, **명단에 없는 닉**(오추출 의심).
- 신규↔이탈을 짝지어 **개명/부캐 접속**을 추정한다. 확실하지 않으면 **추측으로 고치지 말고** 사용자에게 확인받는다(냠순·딩띠 사례처럼). 명단에 없는 닉은 오추출일 확률이 높으니 확대 재확인하거나 사용자에게 묻는다.
- 이때 **정중한 협력 어조**로, 확정된 것과 확인 필요한 것을 분리해 제시한다.

### 6) XLSX 생성 → 제시
`references/pipeline.md`의 실행 예시대로 데이터 JSON을 만들고 스크립트로 생성, `present_files`로 전달. 요약(총원·합계·TOP3·본캐 환산 목록·확인 필요 항목)을 붙인다.

### 7) 업로드 안내
사용자 승인 후, **로컬 PC에서** 실행할 명령어를 안내한다(AWS 자격증명이 로컬에 있어 Claude 샌드박스에선 DynamoDB 접근 불가):
```
python upload_to_dynamodb.py guild_members_YYYYMMDD_MMDD.xlsx <WEEK_KEY>
```
`WEEK_KEY`는 **주차 종료일**(YYYYMMDD). 파일은 `upload_to_dynamodb.py`와 같은 폴더에 둔다. 정정/재업로드·덮어쓰기 주의사항은 `references/pipeline.md` 참고.

## 참고 파일
- `references/pipeline.md` — 상세 규칙, 정규화·개명 대장, 컬럼 레이아웃, 확대 팁, 업로드·정정 절차, 실행 예시. **본캐 환산·정규화·개명·업로드를 다루기 전 반드시 이 파일을 먼저 읽을 것.**
- `scripts/generate_xlsx.py` — 파라미터화된 XLSX 생성기 + 교차검증기. 직접 openpyxl 코드를 새로 짜지 말고 이 스크립트를 쓴다.

## 어조
사용자는 이 파이프라인을 매주 돌리는 길드장이며 LLM 전문용어에 익숙하지 않을 수 있다. 정중·친절하게, 확정/미확정을 명확히 구분해 전달한다. 개명·오추출은 임의로 확정하지 말고 확인받는다.
