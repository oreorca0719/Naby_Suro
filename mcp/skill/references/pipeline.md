# 파이프라인 상세 규칙

## 1. 컬럼 레이아웃 (인게임 캡처)

`닉네임 | 직업 | 레벨 | 직위 | 주간미션 | 지하수로 | 플래그레이스`

- **지하수로** = 추출 대상 점수(큰 숫자, 천단위 콤마).
- **직위** = 나비 / 마스터 / 부마스터 / 꽃미남 / 나방 / 사유미접 / 신입 등(길드 등급). 출력엔 안 쓰지만 0점·미참 판단에 참고.
- **주간미션** = 참여 횟수(대개 10). 출력엔 안 쓴다.
- 출력 XLSX엔 **닉네임/직업/지하수로**만 쓰고 순위는 정렬 후 1부터 부여.

## 2. 본캐 환산 (괄호 규칙) 상세

| 표시 형태 | 본캐 | 직업 처리 |
|---|---|---|
| `A` (괄호 없음) | A | 행에 보이는 직업 그대로 |
| `A(A)` (안=밖) | A | 그대로 (본캐 접속 중) |
| `A(B)` (안≠밖) | **B** | 행 직업은 접속 중 **부캐** 것 → **본캐 B의 직업으로 백필**(직전 주 xlsx에서) |

- 게임이 괄호 안을 `..`로 잘라 못 읽는 경우: (1) 명단에서 해당 부캐가 인접 배치된 본캐, (2) 직전 주 동일 점수대·직위·직업 연속성으로 추정 → **사용자에게 확인**.
- 실제로 겪은 부캐→본캐 예: BloodyMary→멜빵군, 젠빵군→멜빵군, 뽀채현→꼬마로엘, 고장난코딩→코딩시로, 골총→분사, 잭슈패로우→은종욱딱까리, alsdyd나워/alsdyd보마→alsdyd9999, 레트네뜨→리프라드, 벌렌이→벌똥이, 보유무/뵤유무→례에엥, 치설렌→인명재해, 길가던교황→외칼, 수중소녀→경찐, 설렘비고→삿치, jmttm→독쓰는불닭, popebear→혼종곰, 가찬리→찬놈, 우와(부캐)→우와블, 테레입니돠→렌피한. (매주 달라질 수 있으니 그 주 화면 + 명단으로 판단.)

## 3. 개명 대장 (확인된 것 — 옛 닉으로 통일)

대시보드 이력 연속성을 위해 **개명은 옛(기존) 닉으로** 기록한다.

| 현재 인게임 닉 | 기록할 본캐(옛 닉) | 비고 |
|---|---|---|
| 딩띠 | **딩팬무** | 개명 확인됨 |
| 냠순 | **미니냥이** | 2026-07-06 개명, 확인됨 |

- 새 개명이 의심되면(신규↔이탈 짝) 사용자에게 확인 후 이 표에 추가하는 것을 제안한다.
- 탈퇴한 사람의 부캐가 새로 뜨는 경우(예: 서멍청 탈퇴 후 부캐 북이레테)는 **합치지 않고 독립 인원으로 둔다** — 사용자 확인 필요.

## 4. OCR 정규화 표 (자주 나오는 오독 → 정식)

| 오독 | 정식 |
|---|---|
| 워드브레이커 | **윈드브레이커** (직업, 최우선) |
| 츄주 | 츄쭈 |
| 바이루홀 | 바이루욜 |
| 몬가 | 몬갸 |
| 토77기검사 | 토77l검사 |
| MONCLER | M0NCLER (숫자 0) |
| 서수연 | 서쑤연 |
| 표애진 | 표얘진 |
| 찬존 | 찬죤 |
| 낭나힛 | 냥나힛 |
| 킹쪽 | 킹족 |

원칙: **그 주 제공된 명단에 있는 철자**로 맞춘다. 명단에 없는 닉이 나오면 오독 의심 → 확대 재확인 또는 사용자 확인. (명단 스냅샷이 개명 직후라 아직 반영 안 됐을 수도 있으니, 없다고 무조건 오독은 아님.)

## 5. 저해상도 캡처 확대 팁

카카오톡 저화질 캡처에서 닉/괄호가 안 읽힐 때 Python(PIL)로 크롭·확대해서 다시 본다:
```python
from PIL import Image
im = Image.open(path); w,h = im.size
# 닉네임 칸(좌측 ~0~30%)에서 특정 행 근처를 크롭 후 4~6배 확대
c = im.crop((0, int(h*y0), int(w*0.30), int(h*y1)))
c = c.resize((c.width*5, c.height*5)); c.save('/home/claude/crop.png')
```
`view`로 확인. 게임이 셀 자체를 `..`로 자른 경우는 픽셀로도 복구 불가 → 명단/연속성 추정 + 사용자 확인.

## 6. 실행 예시 (XLSX 생성 + 교차검증)

추출·정규화·본캐 환산을 끝낸 뒤 데이터를 JSON으로 저장하고 스크립트를 돌린다.

```bash
# data.json 형태: {"rows": [["닉","직업",점수], ...]}  (순위는 스크립트가 정렬 후 부여)
python scripts/generate_xlsx.py \
  --data data.json \
  --out /mnt/user-data/outputs/guild_members_20260709_0715.xlsx \
  --last /mnt/user-data/outputs/guild_members_20260702_0708.xlsx
```
- `--last` 를 주면 직전 주 xlsx와 대조해 **신규/이탈/중복/닉수**를 출력한다(교차검증).
- 스크립트가 정렬·서식·TOP3 음영·헤더 고정·`윈드브레이커` 잔존 체크를 처리한다.
- 결과 파일을 `present_files`로 전달.

## 7. 업로드 · 정정 절차

- 업로드는 **사용자 로컬 PC**에서만(AWS 자격증명·네트워크가 로컬에 있음, Claude 샌드박스는 DynamoDB 접근 불가). 명령어:
  ```
  python upload_to_dynamodb.py guild_members_YYYYMMDD_MMDD.xlsx <WEEK_KEY>
  ```
- **WEEK_KEY = 주차 종료일**(YYYYMMDD). 예: 0709~0715 → `20260715`.
- xlsx는 `upload_to_dynamodb.py`와 **같은 폴더**에 두거나 전체 경로를 큰따옴표로 감싼다.
- **잘못된 주차로 올렸을 때**: `put_item`은 같은 (week, rank) 키만 덮어쓰므로, 새 파일이 더 짧으면 초과 순위의 옛 행이 **잔존**한다. 그래서 안전하게는 삭제 후 재업로드:
  ```
  python delete_week.py <잘못된_WEEK_KEY>
  python upload_to_dynamodb.py guild_members_YYYYMMDD_MMDD.xlsx <올바른_WEEK_KEY>
  ```
  (`delete_week.py`가 없으면 스키마 확인 후 생성 제안. 기본 가정: 테이블 `maple_guild`, 리전 `ap-northeast-1`, PK=`week`, SK=`rank`.)

## 8. 산출물 관례

- 파일명: `guild_members_시작YYYYMMDD_종료MMDD.xlsx`.
- 0점 인원 포함(직위 나방/사유미접/신입 등). 합계·TOP3·총원을 요약에 표기.
- 응답 말미에 업로드 명령어(WEEK_KEY=종료일)를 제시.
